# Transaction Accounting System Update

## Problem Solved
Manual transactions added by property owners were **not being included** in the balance calculations shown in the properties template. This caused incorrect balance displays.

## Root Cause
The `RentAccountStatus` service was counting ALL confirmed transactions without distinguishing between:
- **Legacy transactions** (manual entries by owners)
- **Invoice-linked transactions** (automated system entries)

This could cause **double-counting** where a transaction linked to an invoice would be counted both in the invoice's `paid_amount` AND in the manual transaction totals.

## Solution Implemented

### 1. Updated `services.py` - RentAccountStatus Class

#### Transaction Type Accounting:

**Transactions that INCREASE balance (Charges/Debits):**
- `invoice` - Manual invoice entries
- `fee` - Late fees or other charges
- `debit` - Additional charges/adjustments

**Transactions that DECREASE balance (Credits/Payments):**
- `receipt` - Payment receipts
- `credit` - Credit memos/adjustments
- `pago` - Payment records

#### Key Changes:
```python
# OLD CODE (could double-count):
charge_transactions = transactions.filter(
    type__in=['invoice', 'fee', 'debit'],
    status='confirmed'
)

# NEW CODE (prevents double-counting):
legacy_charge_transactions = transactions.filter(
    type__in=['invoice', 'fee', 'debit'],
    status='confirmed',
    is_legacy_only=True  # ✅ Only manual transactions
)
```

#### Balance Calculation Formula:
```
Total Balance = 
    Invoice Amounts (from Invoice model)
  - Invoice Payments (from Payment model)
  + Late Fees (from Invoice model)
  + Legacy Manual Charges (debits, fees, manual invoices)
  - Legacy Manual Payments (credits, receipts, pagos)
```

### 2. Updated `views.py` - add_transaction Function

**Explicit Fields Set:**
- `is_legacy_only = True` - Marks this as a manual transaction
- `payment_method = 'other'` - Default method for manual entries
- `status = 'confirmed'` - Auto-confirmed since owner created it

### 3. Transaction Lifecycle

#### Automated Invoice Transactions:
```python
# Generated by tasks.py - generate_invoices()
Transaction.objects.create(
    type='invoice',
    is_legacy_only=False,  # ✅ Linked to invoice system
    invoice=invoice_object,
    ...
)
```
- Created automatically when monthly invoices are generated
- Linked to Invoice model via `invoice` field
- NOT counted in legacy transaction totals (prevents double-counting)

#### Manual Owner Transactions:
```python
# Created via add_transaction view
transaction = form.save(commit=False)
transaction.is_legacy_only = True  # ✅ Manual entry
transaction.status = 'confirmed'
transaction.payment_method = 'other'
transaction.save()
```
- Created manually by property owners
- NOT linked to Invoice model
- COUNTED in balance calculations

#### Owner Payment Registration:
```python
# Created via report_payments view (owner registers payment received)
Transaction.objects.create(
    type='pago',
    is_legacy_only=True,  # ✅ Audit trail
    status='confirmed',
    ...
)
```
- Creates both Payment and Transaction records
- Transaction marked as legacy for audit trail
- Payment updates invoice status

## Status Dictionary Return Values

The `RentAccountStatus.get_status()` method now returns:
```python
{
    'is_past_due': bool,
    'days_past_due': int,
    'balance_owed': Decimal,           # Total amount owed
    'total_invoiced': Decimal,         # From Invoice model
    'total_paid': Decimal,             # From Payment model
    'total_late_fees': Decimal,        # From Invoice model
    'legacy_charges': Decimal,         # ✅ NEW: Manual charges
    'legacy_payments': Decimal,        # ✅ NEW: Manual payments
    'status': str,
    'next_due_date': date,
    'next_due_amount': Decimal,
    'late_fee_info': dict,
}
```

## Usage in Properties Template

```python
# In properties view
from .services import RentAccountStatus

for rent in rents:
    status = RentAccountStatus(rent).get_status()
    rent.balance_owed = status['balance_owed']
    rent.days_past_due = status['days_past_due']
```

The balance now correctly includes:
- ✅ Unpaid invoice amounts
- ✅ Confirmed invoice payments
- ✅ Late fees
- ✅ **Manual charges** (debits, fees, manual invoices)
- ✅ **Manual payments** (credits, receipts, pagos)

## Testing Scenarios

### Scenario 1: Manual Charge
1. Owner adds manual debit for $50
2. Transaction created with `is_legacy_only=True`
3. Balance increases by $50 ✅

### Scenario 2: Manual Payment
1. Owner adds manual receipt for $100
2. Transaction created with `is_legacy_only=True`
3. Balance decreases by $100 ✅

### Scenario 3: Automated Invoice
1. Celery task generates monthly invoice for $500
2. Creates Invoice + Transaction with `is_legacy_only=False`
3. Balance shows $500 from invoice (not double-counted) ✅

### Scenario 4: Mixed Transactions
1. Invoice: $500 (from Invoice model)
2. Manual payment: -$200 (legacy transaction)
3. Late fee: +$25 (from Invoice model)
4. Manual debit: +$50 (legacy transaction)
5. Total Balance: $500 - $200 + $25 + $50 = **$375** ✅

## Migration Notes

No database migrations required. The `is_legacy_only` field already exists in the Transaction model with `default=True`.

## Files Modified

1. **`main/services.py`**
   - Updated `RentAccountStatus.get_status()` method
   - Added `is_legacy_only=True` filter to prevent double-counting
   - Added `legacy_charges` and `legacy_payments` to return dict

2. **`main/views.py`**
   - Updated `add_transaction()` view
   - Explicitly set `is_legacy_only=True`
   - Set default `payment_method='other'`

## Benefits

✅ **Accurate Balance Calculations** - Manual transactions now properly affect balances
